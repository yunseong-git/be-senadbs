## stats 관련

# upsert할때 : battleLog를 작성하면 stats에도 데이터를 작성해야하는데. 아무래도 통계데이터라 로직을 분리하는게 좋아보임. 심지어 battleLog를 작성하는 user입장에서는 통계에 반영이 되었는지 여부를 알필요는 없음.

-> 백그라운드에서 비동기로 돌린다.
-> 즉, 유저에게는 battleLog가 작성이 완료되었을때 응답을 보내고, stats은 다른 쓰레드?에서 맡는다
-> 워커쓰레드는 I/O 대기 작업이라 도입할 필요없고. 그렇다고 main EC2에서 worker EC2를 관제를 할수는 없음. 관제를 할 대기열이 필요함
-> SQS 선택, 일단 개발 단계에서는 그냥 백그라운드 비동기로 처리. ec2에 올릴때 도입해보자.

# upsert할때 index관련 : 현재 스키마에서 방어덱 정보와 공격덱 정보를 페어로 인덱스를 걸고 싶음.
-> stat에서 덱정보는 모두 배열로 이루어짐. heroes의 경우에는 각 덱의 영웅배열, skills의 경우에는 영웅-skillindex 페어 배열
-> 근데 몽고DB에서는 두 개 이상의 배열을 복합 index로 걸수 없음. 어찌저찌 넘어가도 버그고 성능도 문제임.
-> 그럼 단일 문자열로 unique key를 만들어서 index를 걸자. 그럼 그냥 autoincrement로?
-> 이러면 유저가 제출한 데이터가 어떤 index값인지 어케 앎? 그럼 쿼리를 추가해야함. 이러면 별로인듯...
-> 그럼 의미가 있게 그냥 영웅objectId를 묶는다? 그럼 스킬은? 스킬까지 묶으면 길이가 엄청남. 아니 스킬말고 영웅3개만 묶어도 문제임
-> 찾아보니 MD5라는게 있음. 영웅 정렬에서 3개 묶어서 crypto로 지문찍어서 저장하면 됨
-> 뭐 빠른 대신 보안엔 취약하다는데, 굳이 보안 신경쓸 데이터는 아님. 그냥 인덱스 용도니깐.
